Security Operations

การปฏิบัติการรักษาความปลอดภัย - เข้ารหัส เฝ้าระวัง จัดการเปลี่ยนแปลง
อธิบายง่ายๆ เหมือนทีมรักษาความปลอดภัยประจำตึก

ตี 3 ทีม SOC (Security Operations Center) ตรวจพบว่ามีคนใช้บัญชี admin login จากต่างประเทศ เจ้าของบัญชีตัวจริงยืนยันว่าไม่ได้ทำ ทีมจึงล็อคบัญชีทันที ตรวจ Log ย้อนหลัง พบว่ารหัสผ่านถูกเดาได้เพราะไม่มี MFA และไม่เคยเปลี่ยนรหัสผ่านมา 2 ปี SIEM ช่วยให้ตรวจจับและตอบสนองได้ภายใน 15 นาที

Symmetric vs Asymmetric Encryption Flow

Encryption (การเข้ารหัส)

Symmetric vs Asymmetric
เปรียบเทียบ:
- Symmetric = คุณกับเพื่อนมีกุญแจเหมือนกัน 1 ดอก ใช้ล็อคและไขตู้เดียวกัน ปัญหา: ต้องส่งกุญแจให้เพื่อนอย่างปลอดภัย
- Asymmetric = คุณมีแม่กุญแจ (Public Key) แจกให้ทุกคนล็อคของส่งมา แต่มีแค่คุณคนเดียวที่มีกุญแจไข (Private Key)
  • AES (Advanced Encryption Standard) - Symmetric, มาตรฐานปัจจุบัน ใช้ทั่วโลก (128/192/256 bit)
  • 3DES - Symmetric เก่า กำลังถูกเลิกใช้
  • RSA - Asymmetric, ใช้กันมาก สำหรับแลกเปลี่ยน Key และ Digital Signature
  • ECC (Elliptic Curve Cryptography) - Asymmetric, Key สั้นกว่า RSA แต่แข็งแรงเท่ากัน

ในทางปฏิบัติ: ใช้ Asymmetric แลกเปลี่ยน Key ก่อน แล้วใช้ Symmetric เข้ารหัสข้อมูลจริง (เร็วกว่า) - วิธีนี้เรียกว่า Hybrid Encryption และ TLS/HTTPS ใช้วิธีนี้

Hashing (การแฮช)

ลายนิ้วมือของข้อมูล
เปรียบเทียบ: ลายนิ้วมือคน - คนละคนมีลายนิ้วมือต่างกัน ดูลายนิ้วมือแล้วรู้ว่าเป็นใคร แต่ดูลายนิ้วมือแล้วสร้างคนขึ้นมาใหม่ไม่ได้ (One-way function)
  • Hash ไม่ใช่ Encryption - ย้อนกลับไม่ได้ (irreversible)
  • ใช้ตรวจสอบว่าข้อมูลถูกแก้ไขหรือไม่ (Integrity check)
  • ใช้เก็บรหัสผ่าน - เก็บ Hash แทนรหัสจริง ถ้า DB หลุด แฮกเกอร์ได้แค่ Hash
  • SHA-256 - มาตรฐานปัจจุบัน (Secure Hash Algorithm)
  • MD5 - เก่า ไม่ปลอดภัยแล้ว (Collision attack ได้)
  • Salt - เพิ่มค่าสุ่มก่อน Hash เพื่อป้องกัน Rainbow Table Attack

Digital Signatures และ PKI

ลายเซ็นดิจิทัล และ Public Key Infrastructure
เปรียบเทียบ Digital Signature:
เหมือนประทับตราครั่งบนจดหมายสมัยก่อน - รู้ว่าใครส่ง (Authentication) และยังไม่ถูกเปิด (Integrity) ผู้ส่งปฏิเสธไม่ได้ว่าไม่ได้ส่ง (Non-repudiation)
  • Digital Signature - ใช้ Private Key ของผู้ส่งเซ็น ผู้รับใช้ Public Key ตรวจสอบ ให้ทั้ง Authentication + Integrity + Non-repudiation
  • PKI (Public Key Infrastructure) - ระบบทั้งหมดที่จัดการ Digital Certificate รวมถึง CA, RA, CRL
  • CA (Certificate Authority) - "กรมการปกครอง" ที่ออกบัตรประชาชนดิจิทัล ยืนยันว่า Public Key นี้เป็นของคนนี้จริง
  • Certificate - ไฟล์ที่ผูก Public Key กับตัวตนเจ้าของ รับรองโดย CA

Change และ Patch Management

การจัดการเปลี่ยนแปลง และ การอัปเดตแก้ช่องโหว่
เปรียบเทียบ Change Management: ถ้าจะรื้อห้องน้ำในคอนโด ต้อง: ขออนุญาตนิติฯ ก่อน → ประเมินผลกระทบ → อนุมัติ → ทำในวันที่กำหนด → ตรวจรับ ไม่ใช่ลุยรื้อเลยแล้วค่อยบอกทีหลัง
  • Change Management - กระบวนการที่มีขั้นตอน: Request → Impact Assessment → Approval → Test → Implement → Document → Review
  • Patch Management - อัปเดตซอฟต์แวร์เพื่อปิดช่องโหว่ ต้องทำเป็นประจำ ทดสอบก่อน Deploy จริง
  • Configuration Management - จัดการ Baseline ของระบบ ถ้ามีการเปลี่ยนแปลงต้องบันทึก เพื่อให้ย้อนกลับได้

ทำไมสำคัญ: 60%+ ของเหตุ Security Incident เกิดจาก Unpatched System หรือ Misconfiguration ที่ไม่มีการจัดการ

SIEM และ Logging

Security Information and Event Management
เปรียบเทียบ SIEM: ศูนย์ควบคุมความปลอดภัยของห้าง - จอมอนิเตอร์ 50 จอรวมภาพจากกล้อง ระบบแจ้งเตือนไฟไหม้ ระบบบัตรผ่าน ทั้งหมดมาอยู่ที่เดียว ถ้ามีเหตุผิดปกติ แจ้งเตือนยามทันที
  • SIEM - รวม Log จากทุกระบบ (Firewall, Server, App) มาวิเคราะห์หา Pattern ผิดปกติ แจ้งเตือน Real-time
  • Log - บันทึกเหตุการณ์ ใคร ทำอะไร เมื่อไหร่ จากไหน สำคัญมากสำหรับ Forensics
  • Correlation - เชื่อมโยง Event หลายตัว เช่น "Login ผิด 50 ครั้ง + Login สำเร็จจาก IP ต่างประเทศ" = อาจถูก Brute Force
  • Alerting - แจ้งเตือนทีม SOC เมื่อพบ Pattern น่าสงสัย

DLP (Data Loss Prevention)

ป้องกันข้อมูลรั่วไหล
เปรียบเทียบ: เจ้าหน้าที่ศุลกากรตรวจกระเป๋าที่สนามบิน - ตรวจว่ามีของต้องห้ามออกนอกประเทศหรือไม่ DLP ตรวจว่ามีข้อมูลสำคัญ (เลขบัตรเครดิต, ข้อมูลลูกค้า) กำลังจะถูกส่งออกนอกองค์กรหรือไม่
  • Endpoint DLP - ตรวจที่เครื่อง PC เช่น ห้าม Copy ข้อมูลลง USB
  • Network DLP - ตรวจ Traffic ที่วิ่งออก เช่น ห้ามส่ง Email ที่มีเลขบัตรเครดิต
  • Cloud DLP - ตรวจข้อมูลที่อัปโหลดขึ้น Cloud Storage

Data Security Lifecycle

วงจรชีวิตความปลอดภัยข้อมูล
เปรียบเทียบ: เอกสารลับราชการ - สร้างขึ้นมา → ตีตรา "ลับ" → เก็บในตู้ล็อค → ส่งต่อเฉพาะคนที่มีสิทธิ์ → เก็บรักษาตามระยะเวลาที่กำหนด → ถึงเวลาทำลายด้วยเครื่องย่อยกระดาษ
  • Classification - จัดระดับข้อมูล: Public / Internal / Confidential / Top Secret
  • Handling - วิธีจัดการข้อมูลแต่ละระดับ เช่น Confidential ต้องเข้ารหัสเมื่อส่ง
  • Retention - เก็บข้อมูลนานเท่าไหร่ ตามกฎหมายและนโยบาย
  • Destruction - ทำลายอย่างปลอดภัย: Shredding (กระดาษ), Degaussing (แม่เหล็ก), Cryptographic Erasure (ลบ Key)
